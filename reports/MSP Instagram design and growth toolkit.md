# Render MSP's data crisply, then test what spreads

MySpeedPuzzling should make every Instagram asset on one code-first stack that Claude Code drives end to end. A single Chromium page (Playwright 1.64) lays out HTML/CSS with Observable Plot or D3 charts, a CSS tile map with open-licensed flags, OKLCH colour tokens built with culori, self-hosted Rubik with tabular figures, and puzzle pieces from one shared jigsaw generator; it captures PNG, and sharp encodes the 1080×1350 JPEG at quality 93 with full 4:4:4 colour. That generator answers the owner's one hard verdict: the XP share card's concept was liked, but its pieces were blurry and wrong, and vector pieces cut from shared edges can be neither. Motion should reuse the same markup through HyperFrames (Apache-2.0, plain HTML plus GSAP, an official Claude Code plugin), which also suits the feature-explainer videos the owner now wants; Remotion stays the fallback after a one-day bake-off, partly because its company licence now carries a $100/month minimum. ffmpeg finishes video, Blender renders hero pieces, and audio stays SFX-first. AI enters only as a masked "material pass" whose protected pixels are pasted back and diff-checked, in quiet hours, behind a measured calm-machine gate. Growth depends less on more charts than on mechanics: 300–800-character captions in a puzzler's voice with 2–4 hashtags, celebratory tags limited to players the app already shows publicly, carousels as the base and Trial Reels as cheap bets, series run in seasons of 8–12 episodes with a one-in-three novelty budget, and one pre-registered test at a time against the account's own median reach of ~900 (a realistic "viral" is ~9,000). Two items are time-sensitive: the Instagram token probably expires in mid-November, and a few profile handles saved as bare "instagram.com/…" links render broken on the site and would break tags. The WJPC traffic deadline the research flagged no longer matters, because the owner has since ruled out traffic-based posts. The next two weeks should deliver the token build, the piece generator, a nine-direction design lab judged on a phone mock, and the first three owner-approved posts.

## One Chromium page can render every static pixel crisply

### The browser composes; a separate encoder writes the JPEG

The strongest reason to keep **Playwright with Chromium** as the only layout engine is consistency, not features. Charts, tile maps, puzzle pieces and type that share one page also share one font stack with real Rubik metrics and one set of CSS variables, so labels fit and colours match. Every extra engine brings its own text renderer, and that drift is the commonest source of the slightly-off look that reads as cheap. **Playwright 1.64.0 (7 October 2026) bundles Chromium 156**, its builds are already cached on the Mac, and it launches Chromium with `--force-color-profile=srgb` by default ([Playwright releases](https://github.com/microsoft/playwright/releases); [chromiumSwitches.ts](https://raw.githubusercontent.com/microsoft/playwright/main/packages/playwright-core/src/server/chromium/chromiumSwitches.ts)). Claude drives it with a short Node script: one persistent browser, a 1080×1350 or 1080×1920 viewport at device scale 1, JSON data injected into a local template, a wait on `document.fonts.ready` plus a `window.__ready` flag that the charts set when done, then a screenshot ([static toolchain note][n-static]). Templates are HTML partials with JSON props, so Claude chooses a component, its data and its copy, never free-form CSS.

One step changes from round 1. Chromium's DevTools screenshot code hands the bitmap straight to its JPEG encoder with nothing but a quality setting, so the file is untagged and chroma subsampling cannot be controlled ([page_handler.cc](https://chromium.googlesource.com/chromium/src/+/main/content/browser/devtools/protocol/page_handler.cc)). The pipeline should therefore **capture PNG and encode once with sharp 0.35.5 at quality 93, 4:4:4 chroma and an attached sRGB profile**; sharp's own defaults are quality 80 and 4:2:0 ([sharp output docs](https://sharp.pixelplumbing.com/api-output)). Subsampling matters for MSP's coral and indigo text. In a local simulation with 18–28 px text, a 4:4:4 upload still scored 35.4 dB PSNR after a second q75 4:2:0 pass standing in for Instagram's re-encode, against 33.8 dB for a 4:2:0 upload ([static toolchain note][n-static]). Encoder efficiency does not matter: slides weigh 50–600 KB against an 8 MB limit, and jpegli is not even installed. ImageMagick, already on the Mac, is the zero-install fallback, and a preflight `magick identify` must report 1080×1350, 1×1 sampling and Q=93 before any upload. What Instagram does on upload is undocumented; vendor blogs claim a q70–85 re-encode, so one upload of 1080- and 1440-wide variants to a private test account, downloaded and inspected, should settle the width and texture rules.

The alternatives have improved but remain alternates. **Satori 0.55.1 now lays out with Taffy and supports z-index**, which removes round 1's reason for rejecting it; it stays second choice because its CSS coverage is partial (percentages inside `calc()` work only for sizes, margins, paddings, insets and gaps) and any gap renders silently differently, which an LLM author cannot predict ([Satori README](https://raw.githubusercontent.com/vercel/satori/main/README.md)). Takumi 2.15.2 never reads system fonts and outputs PNG, JPEG, WebP, SVG or PDF, the browser-free option if volume ever grows ([Takumi](https://github.com/kane50613/takumi)). Typst 0.15.1 typesets tabular lining figures and variable fonts deterministically, a good fit for dense leaderboards but not for hero charts ([Typst text docs](https://typst.app/docs/reference/text/text)). Gotenberg 8.37 wraps an older Chromium (152) in a 0.5–0.7 GB Docker image with a flat asset folder and no data injection, which is worth it only if rendering ever becomes a server-side service ([Gotenberg releases](https://github.com/gotenberg/gotenberg/releases)). For standalone SVG such as badge art, resvg 0.48.1 rasterises deterministically with variable- and colour-font support ([resvg changelog](https://raw.githubusercontent.com/linebender/resvg/main/CHANGELOG.md)); librsvg should not get text-heavy SVG.

### Observable Plot for daily charts, D3 for heroes, R only for statistics

**Observable Plot inside the template page** should stay the everyday chart engine. Its specs are the shortest, it themes through CSS, and it ships the unusual forms MSP needs: a `dodgeY` beeswarm, `waffleY` unit charts, `fx`/`fy` small multiples, and `arrow`, `text` and `tip` annotation marks ([Plot dodge docs](https://github.com/observablehq/plot/blob/main/docs/transforms/dodge.md); [Plot waffle docs](https://github.com/observablehq/plot/blob/main/docs/marks/waffle.md)). One caveat is new: **Plot's latest release is still 0.6.17 from 14 February 2025**, about 20 months old, although its main branch kept receiving commits into September 2026 ([npm](https://www.npmjs.com/package/@observablehq/plot)). Hand-written **D3 7.9** modules cover hero graphics, ridgelines (Plot has no ridgeline mark) and exact force-packed beeswarms. R's **ggplot2 4.0.3** with ggridges, ggbeeswarm and ggdist is worth adding only if distribution posts recur; it would run from the 354 MB `rocker/r-ver` image and emit SVG into the HTML template so typography stays in one system ([CRAN](https://cran.r-project.org/web/packages/ggplot2/index.html); [Docker Hub](https://hub.docker.com/v2/repositories/rocker/r-ver/tags?page_size=5)).

Several popular options fail the brief. d3-annotation has not been released since 2019 ([d3-annotation](https://github.com/susielu/d3-annotation)). Recharts 3 renders no SVG on the server, because chart size is only set inside an effect ([layoutSlice.ts](https://github.com/recharts/recharts/blob/main/src/state/layoutSlice.ts)). Plotly 4 needs Chrome for Kaleido and adds a "Share chart" button by default ([Plotly v4](https://plotly.com/javascript/guides/whats-new-in-v4/)). Datawrapper's free plan is PNG-only with a mandatory credit, and custom fonts and themes cost a **$499/month add-on** ([Datawrapper pricing](https://www.datawrapper.de/pricing)). Flourish requires a hyperlinked credit on social posts, which an image cannot carry ([Flourish terms](https://flourish.studio/terms)). No benchmark of how accurately LLMs write chart code in each library was found, so any ranking by authoring reliability is opinion; a render, look and fix loop matters more than the engine.

### Tiles, not world maps, for 84 countries

MSP's country stories span 84 countries and lean heavily European, and a world map is the wrong container for them. On a 1,000-px-wide Equal Earth map Czechia is about 8×8 px and Malta half a pixel, the problem Datawrapper's Lisa Charlotte Muth describes when small countries end up "five pixels" on a choropleth ([Datawrapper](https://www.datawrapper.de/blog/weekly-chart-turnout); [static toolchain note][n-static]). The default should be a **hand-tuned CSS-grid tile map**, one equal tile per country holding a circle flag, ISO code and value, plus ranked bar or dot charts for "fastest country" stories. Claude maintains a `tilegrid.json` of column and row per country, seeded from geofacet's MIT-licensed grids rather than Schwabish's CC BY-SA layout ([geofacet](https://github.com/hafen/geofacet); [PolicyViz](https://policyviz.com/2017/10/12/the-world-tile-grid-map/)). It lays out only MSP's actual countries, with a 9–10-column Europe block (tiles of roughly 90–100 px) inside the central ~1,012 px, and colours them with a quantile or log scale. Flags come from **circle-flags 2.8.3 (MIT)**, vendored locally ([circle-flags](https://github.com/HatScripts/circle-flags)).

For true "global reach" visuals, use visionscarto-world-atlas at 50m, which places Crimea in Ukraine and gives Kosovo a code. The older world-atlas package has been archived since March 2023; its 110m file lacks Malta, Singapore and Liechtenstein, and a point in Simferopol falls inside Russia ([topojson/world-atlas](https://github.com/topojson/world-atlas); [visionscarto](https://github.com/visionscarto/world-atlas)). Project with Equal Earth, separate proportional circles with a d3-force collision pass, add a Europe inset, and label only the top ten. Bertin.js (no commits since 2023) and MapLibre basemaps (legible OpenStreetMap attribution required on images) do not fit ([Bertin](https://github.com/neocarto/bertin); [OSMF guidelines](https://osmfoundation.org/wiki/Licence/Attribution_Guidelines)).

### The brand's colours and font impose hard rules

Two measured facts constrain every layout. **Coral #EC726F reaches only 2.92:1 against white and sky #69b3fe 2.22:1**, both below WCAG's 4.5:1 for text and even its 3:1 bar for large text. Coral on navy reaches 4.29:1, enough only for large text, while indigo #4e54c8 (6.13:1) and navy #2b3445 (12.5:1) are text-safe on white ([design references note][n-design]; [W3C contrast](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)). Coral is therefore a fill and highlight colour, outlined in navy wherever it must meet the 3:1 non-text bar ([W3C non-text contrast](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)), and highlighted text on light grounds uses indigo or navy. Colour-blind simulation adds a second rule: **coral against green collapses** (ΔE 16 under deuteranopia), while coral against indigo stays robust under every deficiency type, so any "better/worse" pair is coral versus indigo, never coral versus green ([design references note][n-design]; [Datawrapper colour-blind check](https://www.datawrapper.de/blog/colorblind-check)). Tints, shades and data ramps are generated once, at build time, in OKLCH with **culori 4.0.2**, gamut-mapped explicitly because Chrome and Safari clip out-of-gamut colours instead of mapping them, checked against WCAG 2 and frozen as hex tokens ([Evil Martians](https://evilmartians.com/chronicles/oklch-in-css-why-quit-rgb-hsl); [culori](https://culorijs.org/api/)). Context marks use a light grey (L* around 88–92), different in lightness from coral, so the one-highlight device survives protanopia.

**Rubik's default digits are proportional** (advance widths from 497 to 683 units in the Bold), so `font-variant-numeric: tabular-nums` is mandatory on every time, axis and counter. Rubik has lining figures only, a proper U+2212 minus, and no thin space, so thousands take commas ([design references note][n-design]). The Google Fonts Latin subset drops the `case`, `zero` and `sups` features, so the full variable font should be self-hosted ([Rubik metadata](https://raw.githubusercontent.com/google/fonts/main/ofl/rubik/METADATA.pb)). A serif for "story" headlines (Newsreader or Source Serif 4) and JetBrains Mono for stopwatch numerals are lab variables, not defaults. Emoji should not appear in rendered graphics at all, and flags are SVG. Where a stack still needs an emoji font, pin **Noto Color Emoji (OFL)**, because the macOS licence grants no right to distribute rendered Apple Color Emoji ([macOS licence](https://www.apple.com/legal/sla/docs/macOSTahoe.pdf); [noto-emoji](https://github.com/googlefonts/noto-emoji)).

Warmth should come from **restrained, code-native texture**: luminance-only SVG `feTurbulence` grain, coarse, at 6–12% opacity, on large flat fields only and with a fixed seed so a series stays consistent; pure-CSS halftone on hero shapes; and riso-style overprints of two brand inks ([CSS-Tricks](https://css-tricks.com/grainy-gradients/); [static toolchain note][n-static]). Texture must never sit under text or chart marks: in a local re-encode simulation, 40–47% of the grain energy vanished after one Instagram-like pass, and faint grain turned into noise ([static toolchain note][n-static]). Gradients, where used at all, interpolate `in oklch` to avoid the grey dead zone of RGB blends ([Josh Comeau](https://www.joshwcomeau.com/css/make-beautiful-gradients/)). Generative libraries such as p5.js 2.3 and canvas-sketch belong in a one-off, owner-curated texture library, not in per-post templates, because per-post randomness reads as slop.

### One generator makes every puzzle piece correct by construction

The rejected XP share card failed on execution, not idea: the owner liked the concept but found the image low quality and the pieces "awful and blurry" ([owner decisions][decisions]). Both defects disappear when pieces are geometry rather than pixels. Draradech's jigsaw generator is **CC0** and builds each edge from three cubic Bézier curves with a seeded tab size and jitter; because each cut line is generated once and shared by both neighbouring pieces, **the pieces interlock by construction** ([Draradech/jigsaw](https://github.com/Draradech/jigsaw)). Claude should port that maths to a TypeScript generator of about 150 lines that emits closed per-piece outlines, and reconcile it with the `jigsaw_piece()` helper in MSP's badge toolkit so the site and Instagram share one piece shape ([badge-art README](https://github.com/MySpeedPuzzling/myspeedpuzzling.com/blob/main/tools/badge-art/README.md)). From one seed it produces SVG paths for flat pieces (the default), `THREE.Shape` curves for extrusion (with at least 48 curve segments, so tabs do not facet) and JSON control points for Blender. A QA check proves tessellation: the union of piece areas equals the grid area, with no overlaps. Vector pieces are crisp at any size; 3D renders go out at 2× (2160×2700) and are downscaled with Lanczos.

For 3D, Blender Cycles remains the quality ceiling for hero stills, while three.js r186 rasterised in host Chromium on Metal gives quick stills and Reel frames ([three.js releases](https://github.com/mrdoob/three.js/releases)). One report measured 2.7 ms per frame on an M2 Max through ANGLE-Metal against 49–58 ms on the SwiftShader fallback, so Claude must probe the WebGL renderer string and abort if it is not Metal ([game-harness PR](https://github.com/jbcom/game-harness/pull/34)). WebGL never runs inside Docker on a Mac, because Docker Desktop's GPU passthrough exists only on Windows ([Docker docs](https://docs.docker.com/desktop/features/gpu/)), and three-gpu-pathtracer went WebGPU-only on 28 September 2026, which makes it an experiment at best ([changelog](https://raw.githubusercontent.com/gkjohnson/three-gpu-pathtracer/main/CHANGELOG.md)). For MSP's flat, outlined house style, SVG pieces or Blender toon shading with Freestyle lines will probably look more on-brand than photoreal cardboard; the design lab decides.

### Design tools stay outside the render path

No design tool checked earns a place as the template source of truth. Penpot's official MCP server needs "the Penpot plugin running in an active browser tab" ([Penpot help](https://help.penpot.app/mcp/)). Figma's agent writer runs inside a client, does not yet support custom fonts (which rules out Rubik) and will "eventually be a usage-based paid feature" ([Figma MCP guide](https://help.figma.com/hc/en-us/articles/32132100833559-Guide-to-the-Figma-MCP-server); [Figma write-to-canvas](https://developers.figma.com/docs/figma-mcp-server/write-to-canvas)). Canva's Autofill API needs a paid plan, and Affinity's Claude connector works only while the desktop apps run ([Canva Autofill](https://canva.dev/docs/connect/autofill-guide); [Affinity connector](https://claude.com/connectors/affinity-106b90)). pen.dev is the interesting exception: its CLI can update a template node and export JPEG headlessly, but it is at version 0.3.x, UNLICENSED and not yet priced, and its own materials disagree on whether `.pen` files are an open JSON schema or encrypted ([pen.dev](https://www.pen.dev/); [pen.dev pricing](https://www.pen.dev/pricing)). The source of truth should be **design tokens in DTCG-style JSON plus HTML partials in git**, protected by Playwright screenshot regression against owner-approved golden renders. Figma remains useful as a moodboard: the owner sketches a frame, Claude reads it through the Figma MCP and rebuilds it in HTML. pen.dev deserves a second look in about six months.

## Motion reuses the same markup, and HyperFrames now fits best

### HyperFrames by default, Remotion after a one-day bake-off

Round 1 chose Remotion; round 2 found a better fit for a pipeline whose stills are plain HTML, CSS and SVG. **HyperFrames**, which HeyGen open-sourced in April 2026 under Apache-2.0, renders plain HTML compositions annotated with timing attributes, with no React and no bundler, by seeking each frame in headless Chrome and encoding with FFmpeg; its README promises "same input, same frames, same output" ([HyperFrames](https://github.com/heygen-com/hyperframes)). It animates through GSAP, CSS, Lottie, Three.js, Anime.js or WAAPI, ships 21 agent skills with an official Claude Code plugin, includes chart, map, caption and transition blocks, and shows about 62,000 stars on its repo page ([HyperFrames README](https://raw.githubusercontent.com/heygen-com/hyperframes/main/README.md)). GSAP itself, including the formerly paid plugins, has been free for commercial use since 30 April 2025 ([Webflow](https://webflow.com/blog/gsap-becomes-free)). Motion therefore becomes a paused GSAP timeline laid over the very components the carousels already use, and the same engine fits the **short feature-explainer videos** the owner has asked about ([owner decisions][decisions]); HeyGen describes it as the engine behind its own launch videos ([The Menon Lab](https://themenonlab.blog/blog/heygen-hyperframes-video-as-code)).

**Remotion** remains the more mature engine, with `@remotion/three`, captions, transitions, Lottie and five years of production use, but its pricing moved. It is free for individuals and companies of up to three people, while the company licence page now states a **"Total minimum: $100/month"**, and the unreleased 5.0 will count contractors toward team size and require telemetry or render reporting ([Remotion licence](https://www.remotion.pro/license); [Remotion 5.0 migration](https://www.remotion.dev/docs/5-0-migration)). HyperFrames carries real risks: it is six months old, its README gives no render-speed or Apple Silicon notes and names only MP4 output, and alpha or ProRes output is unverified. A one-day bake-off settles the choice: render the same 12-second "59-minute wall" Reel in both engines and record render time, peak memory, authoring effort and whether two renders are byte-identical. Manim (v0.22, active, with `--seed` for reproducibility) keeps a small niche for mathematical explainers. Motion Canvas has not released since December 2024, Rive needs a paid plan to export, and generated Lottie JSON is verbose with no advantage over SVG plus GSAP ([Motion Canvas releases](https://github.com/motion-canvas/motion-canvas/releases); [Manim releases](https://github.com/ManimCommunity/manim/releases); [Rive export](https://rive.app/docs/editor/exporting/exporting-for-runtime)).

### Data Reels must pay off within eight seconds

Hard evidence on data Reels specifically is thin, so platform-level signals set the design. Instagram's head names watch time, likes per reach and sends per reach as the top ranking signals ([Social Media Today](https://www.socialmediatoday.com/news/instagram-shares-algorithm-insights-2025/738034/)), and **average watch time per Reel was only 8.5 seconds** in Metricool's early-2026 data, even as Reels became the only format with rising engagement ([NetInfluencer on Metricool](https://www.netinfluencer.com/instagram-views-up-27-percent-in-early-2026-as-publishing-increases-report-finds/)). Instagram's 2026 creator guidance describes 3–15 s for quick visual transitions and 15–60 s as the "primary sweet spot" for tutorials ([iPhone in Canada](https://www.iphoneincanada.ca/2026/09/28/instagram-shares-ultimate-blueprint-for-viral-reels-in-2026/)). Newsroom data shorts run longer, about 84 s on average across 50 UK examples with 29 of 33 visualisations animated, but every one had a presenter or voice-over and the study reported no view data ([Online Journalism Blog](https://onlinejournalismblog.com/2026/08/10/how-data-journalism-is-done-on-tiktok-six-key-takeaways-from-watching-50-videos/)). Claims that bar-chart races go viral come from vendor blogs with no measurement ([Data Reel Maker](https://data-reel-maker.lovable.app/blog/why-bar-chart-races-go-viral)). The working rules follow: pose the question or tease the number by about 3 s, resolve it by about 8 s, treat everything after as bonus, cut back to the opening frame so the Reel loops, and burn in every number and label so it works muted. Each Reel gets a dedicated `cover_url` JPEG that shows the question or headline number inside the central 3:4 grid crop, instead of relying on the first frame.

The API limits were re-verified and are unchanged. Reels run **3 s to 15 min and up to 300 MB**, Stories **3–60 s and up to 100 MB**, both as MP4 or MOV with the moov atom first, H.264 or HEVC, closed GOP, 4:2:0, 23–60 fps, at most 1,920 px wide, VBR up to 25 Mbps and AAC at 48 kHz and 128 kbps. `cover_url` overrides `thumb_offset`, Trial Reels publish with `trial_params` set to MANUAL or SS_PERFORMANCE, collaborators are unavailable on Stories, and alt text exists for images only ([IG User Media reference](https://developers.facebook.com/docs/instagram-platform/instagram-graph-api/reference/ig-user/media)). Graduating a manual Trial Reel to followers happens only in the app ([Ayrshare](https://www.ayrshare.com/docs/apis/post/social-networks/instagram.md)). A reasonable render target is 1080×1920 at 30 fps, H.264 High, a fixed 60-frame GOP, `+faststart`, 8–12 Mbps and AAC at 128 kbps, followed by an ffprobe lint after every render (duration of at least 3 s, frame rate, moov position, size limits, an audio stream present). Safe zones are community-derived rather than Meta's; the conservative union keeps Story content within y = 270–1540 and x = 65–1015, and Reel content within y = 220–1250 and x = 60–960, clear of the right-hand action rail ([Inro](https://www.inro.social/blog/instagram-story-size); [House of Marketers](https://houseofmarketers.com/guide-to-safe-zones-tiktok-facebook-instagram-stories-reels/)). Both need checking on a real device.

### Collages and audio stay local, licensed and honest

Collages, mostly from the owner's competition photos, are HTML templates in the same renderer. Flickr's MIT-licensed `justified-layout` returns row geometry that respects mixed aspect ratios ([justified-layout](https://cdn.jsdelivr.net/npm/justified-layout@4.1.0/README.md)). MediaPipe's full-range face detector, suited to back-camera crowd shots, supplies focal points, with smartcrop.js (MIT) as fallback; the template sets `object-position` from them, and a QA check fails any cropped face ([MediaPipe](https://developers.google.com/edge/mediapipe/solutions/vision/face_detector); [smartcrop.js](https://github.com/jwagner/smartcrop.js)). Cut-outs for podium graphics come from macOS's on-device Vision subject-lift request or from **BiRefNet (MIT), which is already installed** ([Apple Vision](https://developer.apple.com/tutorials/data/documentation/vision/vngenerateforegroundinstancemaskrequest.md); [BiRefNet](https://github.com/ZhengPeng7/BiRefNet)). One gentle `.cube` LUT through ffmpeg `lut3d` makes mixed phone cameras consistent ([FFmpeg docs](https://ffmpeg.org/ffmpeg-all.html)), and Real-ESRGAN (BSD-3) brings small photos up to 1080 px ([Real-ESRGAN](https://github.com/xinntao/Real-ESRGAN)). Generative face enhancement (GFPGAN, SeedVR2) must never touch identifiable puzzlers, because it can change faces; and EXIF and GPS data are stripped on ingest.

The account publishes through Instagram Login, and Meta's Audio API for licensed music requires Facebook Login, so every Reel must carry its own embedded audio ([Audio API](https://developers.facebook.com/documentation/instagram-platform/content-publishing/audio-api)). The safest order starts with SFX (ticks on count-ups, whooshes on transitions, a click when a piece lands) from **Freesound CC0** and the Sonniss GDC bundles, which need no attribution but forbid use as AI training data ([Freesound FAQ](https://freesound.org/help/faq/); [GameFromScratch](https://gamefromscratch.com/sonniss-27-5gb-sound-effect-giveaway-at-gdc-2024/)). Next come royalty-free beds from Pixabay or Mixkit without Content-ID marks, or FMA tracks under CC BY ([Pixabay FAQ](https://pixabay.com/service/faq/); [Mixkit](https://mixkit.co/license/); [FMA](https://freemusicarchive.org/License_Guide)), then locally generated beds. Under the owner's stance, model licences are recorded rather than blocking, so hardware and provenance decide. **Stable Audio Open** has the cleanest provenance, trained on about 486,000 CC0, CC BY and Sampling+ recordings from Freesound and FMA; it produces up to 47 s, is free below $1M revenue, and suits loops and effects better than songs ([Stable Audio Open](https://huggingface.co/stabilityai/stable-audio-open-1.0); [Stability licence](https://stability.ai/license)). **ACE-Step 1.5** has an official macOS MLX path, and one user generated two 100-second songs in about 58 s on an M1 Max, but its training data is undisclosed ([ACE-Step](https://github.com/ace-step/ACE-Step-1.5); [DEV](https://dev.to/bigkijimon/100-free-fully-local-ai-music-generation-on-an-m1-mac-ace-step-15-two-100-second-vocal-songs-3h1b)). HeartMuLa is CUDA-first and YuE2 needs a 24 GB NVIDIA GPU, which makes both poor fits for this Mac ([HeartMuLa](https://github.com/HeartMuLa/heartlib); [YuE](https://github.com/multimodal-art-projection/YuE)). Generated music stays in the background and is recorded per asset, since the hobby's distrust of AI art may extend to music. Mastering uses two-pass ffmpeg `loudnorm` to about **−14 LUFS integrated and −1 dBTP**, set explicitly because the filter defaults to −24 and −2; Instagram publishes no official target ([FFmpeg docs](https://ffmpeg.org/ffmpeg-all.html); [OpenClip](https://openclip.app/learn/audio-normalization)). Music ducks 8–12 dB under SFX, and **beat_this (MIT)** places reveals on downbeats deterministically ([beat_this](https://github.com/CPJKU/beat_this)).

## Captions of 300–800 characters, in a puzzler's voice, do the search work

### Hashtags classify; captions get found

Instagram's line since 2025 is that hashtags tell the system what a post is about but do not extend its reach, and since December 2025 the app has been capping them at **five per post**, recommending "fewer (up to 5) more targeted hashtags" ([Social Media Today](https://www.socialmediatoday.com/news/instagram-implements-new-limits-on-hashtag-use/808309/)). Several 2026 guides say the cap counts hashtags in comments too; Meta's API error reference still lists 30, and what the API does with six or more is undocumented ([Meta error codes](https://developers.facebook.com/documentation/instagram-platform/instagram-graph-api/reference/error-codes)). The measured effects are tiny in both directions. Metricool's 24-million-post study found posts with any hashtag got 31.7% fewer views, a correlation more likely about who uses hashtags than about harm ([Metricool](https://metricool.com/press-release-instagram-study-2026/)). Fanpage Karma found five tags about 2% ahead of none and, awkwardly for any middle path, one to three tags slightly behind none ([Fanpage Karma](https://www.fanpagekarma.com/insights/do-instagram-hashtags-work/)). A 2% gap sits far below MSP's noise floor, so the choice should rest on classification and hygiene: **2–4 precise tags on the caption's last line**, always `#speedpuzzling` and `#jigsawpuzzle`, plus one event tag verified in the app or the branded `#myspeedpuzzling`. Never use `#puzzle` (ambiguous with logic games), engagement tags or first-comment hashtags. The pipeline hard-fails above five and warns above four, and an eight-week alternation of zero versus three tags can settle the question for this account.

The real search work happens in words. Instagram says search "results are matched by text" and advises keywords in captions ([Instagram Creators](https://creators.instagram.com/blog/instagram-recommendations-eligibility-tips-creators)), and public posts from professional accounts have been eligible for Google and Bing results since 10 July 2025 ([Storyboard18](https://www.storyboard18.com/digital/instagram-to-make-public-posts-searchable-on-googlebing-74611.htm)). The first sentence should therefore contain the phrase a puzzler would type, such as "500-piece puzzle time" or "speed puzzling record".

### Length, hooks and asks that are not bait

The freshest length data, from 6,126 posts by 168 accounts between July and October 2026, found **51–125-character captions the weakest band (1.38% engagement) and 301–800 characters the strongest (4.57%)**, with longer captions falling back; the source sells scheduling software and the data are correlational ([PostPlanify](https://postplanify.com/blog/instagram-caption-length)). MSP's historical median of 1,069 characters, and 1,745 for the old weekly recaps, sits in the weaker band ([IG API audit](https://graph.instagram.com/v25.0/me/media)). That refines round 1's "short captions": short should mean **300–800 characters for carousels**, 150–500 for single images, 125–500 for Reels, and never more than about 1,000 for reports and recaps. The data belongs on the slides; the caption adds context, a voice and one question. The hook fits in the first ~125 characters before "… more", leads with the surprising number, carries one search phrase, and has no greeting, hashtag or mention (spotlights and records excepted, since the person is the subject).

Questions correlated with 36.7% more comments and comment-focused asks with 202.8% more in Metricool's study ([Metricool](https://metricool.com/press-release-instagram-study-2026/)). Instagram draws the bait line at prompts that elicit fixed interactions, such as "asking people to comment with a specific word, number, or emoji", while calling open-ended questions "a great way to engage with your audience" ([Social Media Today](https://www.socialmediatoday.com/news/instagram-clarifies-advice-on-single-word-ctas-and-longer-reels/718151/)). The operational test is simple: an ask must invite an answer that varies by person ("what's your 500 PB, and was it a first attempt?") or offer real utility (save it, send it to the friend it describes), and send-asks appear in at most one post in three. Each post also gets a pinned comment with the data scope or the owner's own answer, and alt text per slide generated from the facts snapshot, never from the image.

### A puzzler's voice, linted for AI tells

The voice is a fellow puzzler who loves the numbers. The scene's vocabulary is small and precise: solo, pairs (MSP says "duo") and teams; PB, first attempt versus repeat, PPM; "a 500" (usually 513 pieces) and "a 1000" (usually 1,026); edges first, flipping, sorting; Nationals and WJPC ([Completing the Puzzle](https://www.completingthepuzzle.com/blog/how-to-get-started-with-speed-puzzling); [Wikipedia: Jigsaw puzzle](https://en.wikipedia.org/wiki/Jigsaw_puzzle)). Its values are warm, self-aware and competitive but kind; puzzlers describe "a really warm, loving group of people" and joke that the sport is "silly and niche" ([The Independent via AOL](https://www.aol.com/articles/piece-piece-inside-rapid-rise-140501949.html); [Rocky Mountain PBS](https://www.rmpbs.org/news/outdoors/speed-puzzling-growing-colorado)). Humour lands on shared experience (fur, grass, the 59:59 finish), never on a person, and every speed stat sits next to an inclusive median. A competitor's "P4" metric is off-limits ([SpeedPuzzling.com](https://www.speedpuzzling.com/puzzle-ratings.html)). Strava's and Letterboxd's celebrations of collective numbers and Lichess's small-team honesty are worth borrowing. Duolingo's mascot chaos is not, and its May 2025 decision to delete every Instagram and TikTok video after an AI-first backlash is the warning for an AI-drafted account in an AI-wary hobby ([Wikipedia: Duolingo](https://en.wikipedia.org/wiki/Duolingo)).

Every draft therefore passes a lint built from Wikipedia's catalogue of AI writing tells: no em dashes; none of the flagged vocabulary ("delve", "showcase", "vibrant", "leverage" and their kin) or social clichés ("dive in", "game-changer", "thrilled to announce"); no "not X but Y" constructions or reflexive triads; no emoji bullets, Title Case lines or Unicode bold; at most one exclamation mark; and varied sentence length, because strings of short fragments are the newest tell ([Wikipedia: Signs of AI writing](https://en.wikipedia.org/wiki/Wikipedia:Signs_of_AI_writing)). Emoji drop to 0–3 functional ones (a flag, a stopwatch, a trophy, an occasional 🧩 sign-off), a deliberate break from a past in which 82 of 87 captions used them, and worth one test ([captions note][n-captions]). Secondhand summaries of recent studies put the like penalty for labelled AI content at about 7–8% ([Insider Gaming](https://insider-gaming.com/ai-labels-can-reduce-social-media-engagement-study-finds/)). The best defence is the owner's single human touch per caption, saved as `author: human` and reused as a few-shot example.

### Tag to celebrate, collaborate upward

Tagging people correlates with more interactions (+37%) and reach (+17%) in Fanpage Karma's Reels data, while tagging brands correlates with less (−12% and up to −19%) ([Fanpage Karma](https://blog.fanpagekarma.com/2023/06/01/data-driven-study-who-you-should-and-shouldnt-mention-analysis-of-mentions-in-instagram-reels/)). Emplifi's study of 520,000 posts in the first half of 2026 found collaborations lifting shares in every vertical, with small brands' accepted collabs earning five times the interactions of their standard posts and owned carousel collabs lifting least ([Emplifi](https://emplifi.io/resources/instagram-collaborations-boost-organic-engagement/)); an academic study finds that collab reach behaves like a weighted average favouring the smaller partner ([Schöttl](https://hstalks.com/article/11245/download/)). The policy follows from that. Tag only for good news (records, podiums, milestones, spotlights), never in jokes, anomalies or "slowest" framings. Caption mentions for everyone featured go in a credits block below the hook, with image tags on the relevant slide for records and spotlights. Caps are one for a spotlight, the holders for a record, up to nine for the Weekly Numbers, up to twelve for event recaps and fifteen in total, under the API's twenty. The subject is invited as collaborator on spotlights and individual records (the API allows three), organisers on event posts, and for the biggest moments the larger partner is asked to publish and invite MSP. Brands are mentioned only when the post is about their puzzle, and junior-category results appear only once organisers have published them, without image tags. Captions cannot be edited through the API, so a wrong tag must be fixed by hand at once, which makes the tag check the strictest step before approval. Which players qualify is a data question, answered in the section on secondary data.

### German lines, comment replies and the playbook

English stays the default: no study measures bilingual captions, and Instagram has announced no ranking bonus for a second language ([GrowthViral](https://growthviral.co/instagram-news/instagram-edits-bilingual-captions/)). One German line, checked by a native speaker, belongs only on posts about Germany, Austria or Switzerland; Germany is 11.2% of the audience, and German is 8.9% of active MSP players' locales ([IG API audit](https://graph.instagram.com/v25.0/me/insights); [secondary data note][n-data]). If the German share of reach has not moved after about six such posts, the line goes. After publishing, the owner (not the pipeline) answers every comment for the first two hours with a follow-up question or a number, so posts go out at 19:00–21:00 Prague time only when the owner can be on the phone; a read-only comment digest can suggest replies, but Claude never posts them.

The full rule set is a draft **"MSP voice & caption playbook" v0.1** in [§9 of the captions note][n-captions]. It holds the voice principles, a do/don't table, hashtag, emoji and tagging policies, a CTA library by goal, a community glossary with verification status, ten caption skeletons with worked examples, and an eleven-point pre-approval checklist. The owner's edits to the first 10–15 captions should become its examples.

## Shares come from mechanics and tagged people, not from more charts

### Every idea needs a named mechanic

The best-established drivers of sharing are high-arousal positive emotion such as awe and amusement, plus surprise, interest and practical usefulness, each independently linked to virality in Berger and Milkman's study of New York Times articles ([Berger & Milkman](https://www.blueclaw.co.uk/aboutama/documents/jmr_forthcoming/online_content_viral.pdf)). For charts specifically, colourful, unusual forms with recognisable objects are remembered better than common chart types, and clear titles and annotations improve recall ([Borkin et al.](https://vcg.seas.harvard.edu/publications/20130101-what-makes-a-visualization-memorable)). Our World in Data built its Data Insights format because "a clear chart and takeaway" is what gets shared ([OWID](https://ourworldindata.org/launching-data-insights)). Wrapped-style recaps add identity and comparison: Spotify counted 500M+ shares of Wrapped 2025, a company figure ([TechCrunch](https://techcrunch.com/2025/12/04/spotify-says-wrapped-2025-is-its-biggest-yet-with-200m-users-in-its-first-day)). The puzzle niche adds a sobering fact. Discovery has run through video of people doing remarkable things (timelapses, championship clips, sheer scale), and the research found no static puzzle-data post that went viral; Euronews's WJPC 2026 story hooked on secrecy and spectacle ([The Independent via AOL](https://www.aol.com/articles/piece-piece-inside-rapid-rise-140501949.html); [Euronews](https://www.euronews.com/2026/09/21/who-can-solve-it-fastest-speed-puzzlers-race-against-the-clock-at-world-championships)). MSP's own history agrees: the weekly recaps were the most-shared non-giveaway format (161 shares across 29 posts), plausibly because featured puzzlers shared them, and participatory posts reached 2.5–5× the median ([account audit notes][n-audit]). Each brainstormed idea therefore names its primary mechanic (surprise, identity, comparison, utility, debate, send-a-friend, collective milestone or humour) and its primary metric, and ideas that only "report numbers" are rejected.

### What "viral" means at 2,400 followers

Format odds differ by audience. For accounts under 10,000 followers, Fanpage Karma's January–April 2026 data puts median reach per follower at 4.9% for Reels, 3.5% for images and 2.6% for carousels, with **Reels reaching nearly three times as many non-followers as carousels**, while images narrowly lead on interaction rate ([Fanpage Karma](https://www.fanpagekarma.com/insights/instagram-format-reach/)). Carousels still travel through sends and through reposts, which since August 2025 carry public posts into reposters' feeds while crediting the original ([PhoneArena](https://www.phonearena.com/news/instagram-brings-reposts-to-main-feed-in-bid-to-boost-sharing_id172969)). The claim that Instagram re-serves an unswiped carousel from slide 2 is weakly sourced but cheap to design for, so slide 2 should stand alone ([Stack Influence](https://stackinfluence.com/what-are-instagram-carousels-2026-guide/)).

MSP's baseline is unusual: a median regular post reaches **901 accounts, about 37% of followers**, far above the 2.6% benchmark, so most posts already reach mainly followers and lift is hard to buy ([account audit notes][n-audit]). Measured against a rolling 12-post median, a **breakout** is at least 3× (~2,700), **viral at MSP scale** is at least 10× (~9,000) with half or more from non-followers, and a **hit** is at least 30×. The account's best post ever, the WJPC 2026 giveaway at 4,357, reached about 4.8×. A static data carousel reaching 10× is plausible only with a giveaway, a larger collab partner or heavy resharing by tagged players; Trial Reels are the likeliest route to a hit, though most Reels will land below the carousel median ([virality note][n-viral]). Reach, not views, is the denominator, because carousel views run about 2.8 per reached account.

### Seasons, caps and a novelty budget keep the feed fresh

Attention to novel items decays along a predictable curve ([Wu & Huberman](https://arxiv.org/pdf/0704.1158)), and MSP's recap followed it: reach of roughly 900–1,350 in its first quarter sagged to 550–1,100 in the second while template, topic and 1,745-character captions stayed fixed, and the series died in August 2025 ([account audit notes][n-audit]). That decline is confounded by season and caption length, so the rotation rules here are reasoned heuristics, to be replaced by MSP's own data after about three months. Series run in **seasons of 8–12 episodes** and then get a visible retool: a new skin, segment or hook format. Each series keeps one fixed container with rotating segments; the Weekly Numbers, for example, keep three fixed slides and draw two from a pool (guess the number, puzzle of the week, country spotlight, brand duel, one year ago).

Caps prevent sameness. The same template or chart type never appears in consecutive posts or more than twice in seven days; giveaways stay at three a year or fewer and are tied to events; the same featured player appears at most every six weeks unless breaking a record; and product posts stay at two a month. **About one feed post in three spends a novelty budget** on a new template, mechanic or topic, while Trial Reels, which never reach followers' feeds, are unlimited. A series earns a retool when two of three signals fire: its rolling four-episode median of likes or sends per reach falls below 75% of its first four episodes while non-series posts held steady (a difference-in-differences guard against seasonality), Story tap-forward and exit shares rise, or unfollows tick up on series days. Annual rituals such as MSP Wrapped stay scarce on purpose.

### At this size, only big effects can be learned

With a median of 2 shares, 1 save and 1 follow per post, count metrics are too sparse for small effects ([account audit notes][n-audit]). Assuming a per-post log-SD of reach around 0.3, a 2× reach difference needs about 4 posts per arm, a 30% difference about 20 and a 15% difference about 70, which is unrealistic; doubling shares needs about 12 posts per arm, and saves and follows can only be judged by month or pillar ([virality note][n-viral]). The protocol therefore runs **one pre-registered feed test at a time**. Each test is logged before it starts with its hypothesis, single primary metric, arms, fixed n and stop date, runs in alternating weeks on matched slots, and is analysed with a paired sign test (seven wins out of eight pairs gives a one-sided p of about 0.035). Peeking is out: in Evan Miller's example, stopping whenever p fell below 0.05 declared a do-nothing change significant 26.1% of the time ([Evan Miller](https://www.evanmiller.org/how-not-to-run-an-ab-test.html)).

New formats are judged on episodes 3–6, to discount the novelty bump, and event weeks are excluded. A post that broke out to non-followers is not called a loser on likes per reach, since the same Reel drew a 0.7% like rate from non-followers against 1.6% from followers in Kapwing's test ([Kapwing](https://www.kapwing.com/resources/instagram-trial-reels-study-what-we-learned-after-a-trial-reel-hit-1-million-views/)). Trial Reels are the only near-randomised bench: post two or three hook or cover variants of one data story, compare 72-hour views and shares, and promote the winner ([Sprout Social](https://sproutsocial.com/insights/instagram-trial-reels/)). The first four tests should be caption length on the Weekly Numbers (up to 400 versus 600–800 characters), guess-the-number versus plain-fact carousels, tagged versus untagged weekly bests measured on sends per reach, and Trial Reel hook variants. The owner should expect most posts at 0.7–1.5× the median, and real learnings monthly rather than weekly.

### Measurement lives in local SQLite and UTM links

The insights puller stores snapshots at +48 h, +7 d and +30 d in the local SQLite store, with +7 d as the decision point because data can lag 48 hours, and pulls Story metrics within 24 hours, before they expire ([Meta media insights](https://developers.facebook.com/docs/instagram-platform/reference/instagram-media/insights)). The API gives per-post reach, shares, saves, follows, profile visits and reposts, but **no per-post split between followers and non-followers**; that exists only as daily account-level reach broken down by follow type ([Meta user insights](https://developers.facebook.com/docs/instagram-platform/api-reference/instagram-user/insights)), so non-follower share per post is approximated from days with exactly one new post. Each post is also tagged with pillar, series, season, episode, mechanic, template, chart type, featured-player and event flags and test arm, which is what makes the fatigue and test analyses possible.

Grafana's SQLite datasource requires the database file to sit on the Grafana host ([Grafana plugin](https://grafana.com/grafana/plugins/frser-sqlite-datasource/)), so for a laptop-local store the simpler path is to render six weekly panels inside the local review app: plan adherence and zero-post weeks; the last four posts' median reach against the 12-post baseline, with a breakout flag; sends and likes per reach by pillar, with a fatigue panel; non-follower share and net follows; link taps to UTM sessions to sign-ups; and the open experiment, with its result hidden until n is reached. Every link carries lowercase UTMs, because GA4 treats "Instagram" and "instagram" as different sources and in-app browsers often arrive as direct traffic ([link.boo](https://link.boo/guides/instagram-link-click-tracking)): `utm_source=instagram`, `utm_medium=social`, `utm_campaign=<pillar>` and `utm_content=<post id, bio-link or story-link>`. This reconciles two researchers' schemes (one put a dated post slug in the campaign), so GA aggregates by pillar while keeping post-level detail. ## Community tables, not traffic data, hold the next stories

### The database already holds stories beyond solve results

The read-only role reaches several community tables that round 1 did not use, and they carry the texture the feed lacks ([secondary data note][n-data]). **Player moments** logged 1,774 personal bests by 935 players in the last 30 days, already typed and de-duplicated, which makes them the natural feed for weekly shout-outs. The **follow graph** holds 21,418 edges, and the most-followed public player has 711 followers. **Lending** recorded 5,950 transfers, and one title, Bottled Biomes, has passed through 30 different puzzlers' hands. The **marketplace** has 267 transaction ratings, every one five stars, and Ravensburger accounts for 41% of 1,857 hand-overs. **Catalogue curation** shows 392 puzzlers fixing 2,941 entries this year, and feature voting holds 111 open requests with 556 votes. Three cautions apply. Many of these tables start on 5 December 2025, a launch or backfill date, so no year-over-year comparisons exist. Wishlist-to-solved conversion is meaningless (2.8%), because fulfilled wishes are removed automatically. And the app stores no search terms, page views, barcode scans or puzzle ratings at all, by deliberate privacy design ([activity-analytics doc](https://github.com/MySpeedPuzzling/myspeedpuzzling.com/blob/main/docs/features/activity-analytics.md)). Query results are cached locally for design iteration rather than re-queried in loops.

One table sits on the boundary of the owner's new rule. The daily-presence summary (signed-in players per day, tracked since 31 July 2026) shows a 16% rise during WJPC week and a weekend lift, but it measures visits rather than puzzling, so it is closer to traffic than to puzzle data. Until the owner says otherwise, posts should use the solve-based equivalents instead (37.8% of solves happen at weekends, per round 1).

### Observability serves measurement, not content

The owner has ruled out posts based on website traffic from Grafana, Prometheus or Tempo, and a WJPC recap uses puzzle and competition data only ([owner decisions][decisions]). That retires the research's most urgent deadline: WJPC 2026 traffic would have aged out of Prometheus around 16–20 October, and it no longer matters. It also retires the trace-based content ideas (most-viewed puzzles, most-scanned boxes, "wanted" barcodes). What remains is measurement. **GA4 is live on the site but loads only after a real interaction and skips likely bots**, a trade made during a 2026 bot wave, so it will undercount visits from Instagram's in-app browser; it is still the right tool for UTM-tagged links, read through the GA4 Data API's `runReport` with a service account ([secondary data note][n-data]). No acquisition source is stored at sign-up, so linking Instagram to registrations needs an app change. If server-side confirmation is ever wanted, Tempo keeps every Traefik span for 14 days and the app already recognises Instagram's in-app browser by user agent ([InAppBrowser.php](https://github.com/MySpeedPuzzling/myspeedpuzzling.com/blob/main/src/Value/InAppBrowser.php); [usage-statistics doc](https://github.com/MySpeedPuzzling/myspeedpuzzling.com/blob/main/docs/features/api/usage-statistics.md)), but it would need a Grafana token and remains optional. Loki adds little, because production logs only warnings and audit lines.

### Tagging follows the app's visibility rules, one notch stricter

The owner has decided the policy: no opt-in, players are featured the way MSP already shows them, private profiles and ranking opt-outs are respected, a do-not-feature list is honoured, and tags come only from the Instagram handle on the MSP profile ([owner decisions][decisions]). The code adds three implementation details. First, the handle is free text with no validation, normalised only at display time ([GenerateInstagramLink.php](https://github.com/MySpeedPuzzling/myspeedpuzzling.com/blob/main/src/Services/GenerateInstagramLink.php); [EditProfileFormType.php](https://github.com/MySpeedPuzzling/myspeedpuzzling.com/blob/main/src/FormType/EditProfileFormType.php)). Of 977 public handles, 334 start with "@", 160 are URLs, 62 carry query strings, and **943 normalise to a valid handle shape**. About seven are bare "instagram.com/…" values without a scheme, which the site turns into a broken "instagram.com/instagram.com/…" link, a small app bug worth fixing ([secondary data note][n-data]). The pipeline must normalise every value, tag only handles that match `^[A-Za-z0-9._]{1,30}$`, name the player without a tag otherwise, and confirm that the account still exists, since a renamed handle could tag a stranger; whether the API can check that for this account type is unverified.

Second, a **ranking opt-out in the app removes a player only from the MSP Rating ladder**; fastest-player, pair, group and puzzle boards merely carry the flag, and the fastest-players query does not filter on it ([opt-out doc](https://github.com/MySpeedPuzzling/myspeedpuzzling.com/blob/main/docs/features/opt-out.md); [GetFastestPlayers.php](https://github.com/MySpeedPuzzling/myspeedpuzzling.com/blob/main/src/Query/GetFastestPlayers.php)). The pipeline should be stricter than the app and exclude opted-out players from every named feature, which costs almost nothing: 3 handles overall and none in the solo-500 top 100. Third, a private profile is the hard rule ("every mistake must fail towards hiding"), and the XP, achievement, karma, streak and prediction opt-outs add per-post-type filters ([private-profile doc](https://github.com/MySpeedPuzzling/myspeedpuzzling.com/blob/main/docs/features/private-profile-allow-list.md)). Pairs and teams appear only if every linked member passes; events must pass the app's public-visibility condition, with published rounds and non-deleted participants; conversations, chats and private collections are never used. A reusable `safe_player` filter in the secondary-data note encodes all of this ([secondary data note][n-data]).

The resulting pools are workable: **676 taggable players active in 2026** (public, with a handle, no ranking opt-out), 53 of the top-100 solo-500 personal bests, 58 of the 94 players at level 40 or above, and 150 of the 935 players who set a PB in the last 30 days. Only 66 of 837 WJPC 2026 participants qualify, because most competitors have no linked MSP profile. The do-not-feature list holds player IDs, which are personal data, so it must live somewhere gitignored. The repository ignores `content/` but has no entry for a root-level do-not-feature file, so the list belongs under `content/`.

## Nine directions and eight AI labs, judged on a phone by the owner

### What every direction keeps constant

The premium data brands share a kit rather than a look: a title that states the takeaway, one highlight colour against muted context, direct labels and annotation instead of legends, one fixed brand device in a fixed position (The Economist's red rectangle is the archetype), and one chart per idea ([The Data School](https://www.thedataschool.co.uk/johann-shin/visual-storytelling-done-right-5-lessons-from-the-economist); [Datawrapper text rules](https://www.datawrapper.de/blog/text-in-data-visualizations); [OWID](https://ourworldindata.org/launching-data-insights)). Spotify answered the "AI slop" criticism of its 2024 Wrapped with a 2025 edition that was mostly black and white, kept colour for real content and added handmade textures ([Fast Company](https://fastcompanyme.com/?p=46098)). MSP's anti-slop rules follow from these and from its own design system, which already says "not gradient-heavy or neon" and "never dark or heavy" ([design-system README](https://github.com/MySpeedPuzzling/myspeedpuzzling.com/blob/main/docs/design-system/README.md)). There are no gradients except a same-hue wash, and **indigo is used flat only**, since indigo-to-violet gradients are the archetypal AI-startup look ([Claude Marketers](https://www.claudemarketers.com/skills/no-slop-design)). There is no glass, blur, glow or stacked shadow, no generic icon set and no emoji in graphics. Each slide carries one idea, each chart one highlight hue and each slide at most three brand hues; every chart slide has a source line; margins and device coordinates are identical on every slide; and puzzle pieces come only from the generator. Pieces carry meaning or do not appear: Isotype's rules make a piece a legitimate unit mark when it has a fixed value, is grouped for counting and the total is also printed as a number ([Eagereyes](https://eagereyes.org/papers/isotype-visualization); [vis4](http://www.vis4.net/blog/choose-your-icons-wisely/)).

The grid fixes the geometry. Profile thumbnails have been 3:4 since January 2025 ([Neal Schaffer](https://nealschaffer.com/instagram-post-size/)), so a 1080×1350 post keeps 1,012.5 px of its width and loses about 34 px on each side ([Stellar Digital](https://stellardigital.com.au/instagram-size-guide-2025/)). Text and data therefore sit within x = 88–992, a 904-px content width on a six-column grid. A phone shows the 1,080-px canvas at roughly 0.35–0.40 scale, so the type floors are 30 px for source lines, 36 px for labels, 44 px for body text and 88 px for any cover headline meant to read from the grid. Ground colour rotates by pillar while structure stays fixed, and a series marker (a spine or corner tag with series name and issue number) makes the grid read like a shelf of puzzle boxes. Claude may only choose a component (13 are specified, from cover and hero number to unit grid, 60-minute dial and quiz card), its props and its copy, never CSS. A Playwright QA gate measures the rendered DOM and pixels: text sizes and safe areas, WCAG contrast of each text node against its real ground, highlight-hue count, word counts, tabular numerals on every number, loaded fonts with no fallback glyphs, no emoji code points, no blur, backdrop filters or multi-stop gradients, the brand device at its coordinates, a source line, and bars that start at zero. Owner-approved golden renders serve both as regression baselines and as reference images for Claude, as the badge project's QA gate did ([badge-art README](https://github.com/MySpeedPuzzling/myspeedpuzzling.com/blob/main/tools/badge-art/README.md)). The token values are a reasoned v0 for the lab to tune ([design references note][n-design]).

### AI labs work only with composite-back

No diffusion workflow in ComfyUI preserves exact text or geometry on its own: ControlNet, img2img, edit models, relighting and upscalers all re-synthesise every pixel they touch. MSP's badge lab measured it: without composite-back, FLUX.2 klein 4B changed 30–43% of the rim pixels it was meant to keep, and a latent noise mask still changed 3–4% ([AI design note][n-ai]). The workflow that works is **composite-back**. Code renders the protected layers (text, numbers, logo, piece edges), AI works on a separate layer or inside a mask, code pastes the protected pixels back, and a pixel diff proves that nothing protected changed. Blender supplies everything structure-driven AI needs (an exact depth pass, Freestyle lines and an object-ID mask), so AI adds only surface craft such as cardboard fibre, print grain or a soft studio light.

Everything the first labs need is installed: klein 4B in Q8 and bf16, Z-Image Turbo with the Fun ControlNet Union patch (which supports canny and depth, [ComfyUI docs](https://docs.comfy.org/tutorials/image/z-image/z-image-turbo)), Qwen-Image-Edit-2511, BiRefNet and a Qwen2.5-VL-7B critic. klein 9B, non-commercial but allowed under the owner's stance, stays on disk with its licence recorded ([owner decisions][decisions]). Several options are not worth a lab: layerdiffuse (SDXL and SD1.5 only), IC-Light (SD1.5), Qwen-Image-Layered (about 40 GB of bf16 weights for a 20B model), the archived DiffusionKit, SwarmUI and InvokeAI (duplicate model stores), and the ComfyUI MCP's training tool, which launches a CUDA Docker container ([layerdiffuse](https://github.com/huchenlei/ComfyUI-layerdiffuse); [IC-Light](https://github.com/lllyasviel/IC-Light); [Qwen-Image-Layered](https://huggingface.co/Qwen/Qwen-Image-Layered); [DiffusionKit](https://github.com/argmaxinc/DiffusionKit)).

AI output should mostly be a **curated asset library made once**: paper, felt and cardboard plates, light plates, scene plates. The badge lab's AI atlas ran "5 times in total", after which each new asset cost about 2 s of CPU ([AI design note][n-ai]). Every asset records model, licence, seed, workflow hash, references, approval date and critic scores. Consistency comes first from two to five fixed reference images with klein 4B; LoRA training (mflux-train for Z-Image, or SimpleTuner, which claims M3 Max support with 24 GB or more) waits until 20–30 approved library images exist, since no M3 Max training timings were found ([mflux](https://github.com/mflux-community/mflux); [SimpleTuner](https://github.com/bghira/SimpleTuner)). ### Critics: deterministic checks first, Claude second, the owner calibrates

No automated critic reliably catches slop, wrong pieces or off-brand style. Learned preference scorers predict generic crowd taste at roughly 57–85% pairwise accuracy, with HPSv3 the best, and they can reward the very gloss MSP bans: reward hacking with HPSv2 produced "meaningless accessories and decorative light effects" ([HPSv3](https://arxiv.org/html/2508.03789v2)). The best of 19 multimodal models scored 65.5% on a 2026 design-understanding benchmark ([Microsoft Research](https://www.microsoft.com/en-us/research/?p=1169843)), and GPT-class judges correlate "reasonably well" with human design ratings but "cannot distinguish small details" ([Haraguchi et al.](https://arxiv.org/abs/2410.08885)). No published agreement figures for Claude as a design judge were found. The critic stack therefore starts with **deterministic checks**: the protected-pixel diff, palette ΔE against the tokens, piece-mask IoU against the generator's SVG, sharpness, contrast and the DOM lint. A learned scorer only ranks AI-layer candidates, and the shortlist goes to **Claude with a written rubric, a banned-traits list and two or three approved MSP references side by side**, read at phone size. The owner's 30–50 pairwise picks calibrate it, and Claude becomes a gate only after agreeing on at least 80% of pairs, re-checked monthly on ten new pairs. The local Qwen2.5-VL-7B (about 10 GB with its projector) suits OCR-style checks ("is any text visible in this AI layer?") and banned traits rather than taste, and it cannot share memory with a 20 GB diffusion job, so critics run in a separate phase.

### The calm-machine rule, made measurable

On a 36 GB Mac the binding constraint is unified memory, not GPU speed. Reading the installed ComfyUI source shows that `--lowvram` and `--novram` do nothing on Apple Silicon, because the code forces a shared memory state and dynamic VRAM management is NVIDIA-only ([AI design note][n-ai]). The real levers are Q8 GGUF weights, 768–1,024 px, one model family per session, an explicit unload call between families, and `--cache-none` for unattended batches; in the badge lab, `--use-pytorch-cross-attention` and the fp16 flags caused a 27 GB critical spike and black images. Docker Desktop's VM alone is configured for 12 GiB, which is the difference between "klein 4B only" at about 20 GB free and Z-Image with ControlNet or Qwen-Edit at about 30 GB free. During this research, with many agents and apps open, memory pressure already read "warn". Before every heavy job, and between items, a sudo-free calm check must pass:

| Check | Read with | Passes when |
|---|---|---|
| Memory pressure | `sysctl kern.memorystatus_vm_pressure_level` | Normal (1) |
| Free memory | `memory_pressure -Q` | Job's need plus 4 GB (klein ≥24 GB; Z-Image and Qwen-Edit ≥30 GB) |
| Swap | `sysctl vm.swapusage` | Under 2 GB used and not growing over 60 s |
| Co-tenants | Process list | No Docker VM, Blender, local LLM server or second ComfyUI |
| Idle | `ioreg` HID idle time | At least 20–30 min, or inside the window the owner released |
| Power and heat | `pmset -g batt`, `pmset -g therm` | On AC, no thermal warning |
| GPU | `ioreg` accelerator utilisation | Under 10% over 10 s |
| Disk | `df` | At least 10 GB free |
| Engine | ComfyUI `/system_stats` | Responds; queue empty |

A watchdog interrupts, unloads and defers the item if pressure turns critical or swap grows by more than 4 GB. Jobs wait as files in a pending queue grouped by model family, run one at a time with a 15-minute GPU-turn cap, and drain from a launchd agent with `StartCalendarInterval`, which runs on wake if the Mac slept through the slot ([Apple: scheduling timed jobs](https://developer.apple.com/library/archive/documentation/MacOSX/Conceptual/BPSystemStartup/Chapters/ScheduledJobs.html)), wrapped in `caffeinate -i`. The owner's go-ahead stays explicit: the runner only drains a queue the owner has released for that night. Every prototype and lab, light or heavy, appends one JSON line per item to its run log:

Each lab's summary reports n, median and p90 wall time, the maximum peak footprint and pressure, swap growth and total GPU-busy minutes. Peak memory is sampled from the process footprint plus the GPU's "in use system memory", because whether macOS's footprint counter captures all Metal allocations is unverified. macmon adds sudo-free GPU power and temperature readings, though it warns that its CPU and ANE counters may stop updating on the newest macOS ([macmon](https://github.com/vladkens/macmon)). When a bigger machine arrives, L2 and L7 re-run at 1,024 px with the same record format, so results compare directly.

### Gaps the research could not close

Several researchers exhausted their web-search budget and some sources were unreachable, so a few gaps remain; most should be closed by measurement rather than more reading. Nothing in the toolchain has been benchmarked on this M3 Max: Chromium render times, HyperFrames and Remotion renders, EEVEE frames, Z-Image with ControlNet, SeedVR2, Depth Anything 3 and Mac LoRA training are all estimates. Instagram's recompression of uploads (quality, subsampling, whether 1440-px uploads survive) and its safe zones are undocumented. No controlled evidence exists on data-Reel formats, Story sticker participation, puzzle-niche Reels or reply speed. Reddit's puzzle communities could not be fetched, so some glossary humour and slang are unverified, and Instagram's Help Center pages on the hashtag cap rendered empty. The Economist's chart style guide and several design sources were blocked. No benchmark of LLM chart-authoring accuracy or of Claude as a design judge was found. ACE-Step's weight licence, Sonniss's full terms and the licences of individual geofacet grids were not read. GA property details are unknown until access is granted, and Czech, UK, German, Canadian and Australian championship dates were not checked. The plan closes several of these by design: L0 logs every run, DL2 benchmarks motion, and DL3 tests recompression on a real account.

## Conclusion

The research turns the design problem into a correctness problem with a taste problem on top. The owner's one hard verdict, wrong and blurry pieces, is a failure that code can rule out deterministically, and it is the same failure the badge lab saw from every diffusion route it tried. Once correctness is guaranteed by a generator, a DOM lint and a protected-pixel diff, the only open variable is taste, and the scarcest resource is the owner's attention. That is why the labs are built around decisions the owner makes by feel, on a phone, against real context, and why AI is demoted from image maker to finisher with a mechanical guarantee. The calm-machine rule does the same for compute: it turns a vague worry about a 36 GB Mac into a queue, a gate and a log that make every run comparable when a bigger machine arrives.

The growth lever has also moved, from what MSP draws to who shares it. With 676 taggable active players and the visibility rules settled, the old recap's mechanic (people passing on posts that celebrate them) can return without a consent form. The experiment arithmetic adds discipline: at 2,400 followers only twofold effects are learnable within weeks, so hashtag counts and caption micro-variants will never earn their testing time. The programme should put its novelty budget into big structural bets (tagged weekly bests, collabs with larger partners, Trial Reels, feature explainers, MSP Wrapped and event weeks), and judge each against the account's own median rather than against industry benchmarks it already beats.
